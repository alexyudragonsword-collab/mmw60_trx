# 里程碑 3：802.11ay 两种波形（当前真相）

> 范围、取舍与已经量到的。ROADMAP 里程碑 3 记没做的；数字原值在 `cairn/LOG.md`。

## 1. 范围（用户 2026-11-16 定）

- ay 不是第三条拓扑：拓扑 B 的硬件（零中频链、同一前端实例）配第三、四种波形 `ay_ofdm` / `ay_sc`。
- 数字（EDMG OFDM / SC 单信道数字学、MCS 表、DMG / EDMG 的 TX EVM 限值、灵敏度表）只从 spec_sources 进来（铁律 5）。已发 spec_sources#29，本库是发起方，合并后由本库验收并关。2026-11-16 已回（spec_sources#30，pin `3123b65`；键见 `cairn/spec-sources.md`），EDMG 灵敏度没有出处。
- 第一轮只做 EVM 口径（不做编码 PER），只做单信道（不做 2 / 3 / 4 信道绑定）。
- 数字到之前先建与数字无关的部分；`config.WAVEFORMS_BUILT` 不含 ay，`LinkSim` 照样拒绝（`tests/test_laws.py::test_law1_waveform_enum_is_complete_and_ay_refuses`）。

## 2. 骨架（`src/mmw60/ay/`，2026-11-16）

每个模块都把数字学当参数，测试用的是合成数字学（2 的幂、1 GS/s），`tests/test_ay_skeleton.py`。

| 模块 | 内容 | 测试守的 |
|---|---|---|
| `golay.py` | 由延迟向量 D 与权向量 W 递推出 Golay 互补对（802.11ad 写 Ga / Gb 的同一形式；用哪组 D / W 是规范数字） | 任意 D 排列、W ∈ {±1, ±j} 下互补；非法 D / W 报错 |
| `sc.py` | 单载波块：[G \| d₀ \| G \| d₁ \| … \| G]，窗口 [d_b \| G] 前面的 G 就是循环前缀；可选逐样本旋转 e^{jrn}（π/2-BPSK 一族），要求 r·block 是 2π 的整数倍，否则拒绝；互补对各带一段循环前缀做信道估计（DMG CEF 的原理，不是它的布局）；ZF / 去偏 MMSE 频域均衡；用尾部已知 G 逐块跟公共相位 | 信道不长于 G 时估计与 ZF 都精确到数值精度，长于 G 时有块间干扰；flat 信道上 MMSE 读出 SNR（±0.3 dB）且无偏；相位漂移被尾 G 跟住 |
| `ofdm.py` | 任意子载波排布（FFT 点数、CP、采样率、数据 / 导频的有符号索引、导频值）；训练符号估信道、ZF、导频去公共相位；`receive(h=)` 给定信道（PA 隔离读法） | 多径不长于 CP 时精确；逐符号随机公共相位被导频去掉 |
| `papr.py` | 理想插值 / 抽取、根升余弦成形与匹配滤波、PAPR CCDF、`obo_for_evm`（共享 PA 上 EVM 到目标所需的回退） | 往返透明；多音 OFDM 的 1e-3 处 PAPR 是高斯包络的 8.39 dB（±0.3）；回退差约等于 PAPR 差 |

CFO：重复一段长 L 的序列，`rx.cfo.stf_coarse_cfo` 以 L 为滞后估计，范围 ±fs/(2L)，越界按 fs/L 混叠（测试守）。ay 的 L-STF 用哪段序列、重复几次是规范数字。

## 3. 在合成数字学上量到的（不是 ay 的结论）

根升余弦滚降 0.25、4 倍过采样，PAPR（dB，1e-3 / 1e-4）：

| 波形 | 1e-3 | 1e-4 |
|---|---|---|
| OFDM（337 音，QPSK） | 8.36 | 9.50 |
| SC BPSK | 4.87 | 5.03 |
| SC π/2-BPSK | 1.92 | 2.02 |
| SC QPSK | 4.24 | 4.67 |
| SC 16-QAM | 5.47 | 6.23 |
| SC 64-QAM | 5.77 | 6.37 |

EVM 到目标所需的输出回退（dB，从 Psat 算；PA 隔离读法：两边都只去一个复增益，OFDM 不带训练场过 PA）：

| PA | 波形 | −15 dB | −20 dB | −25 dB |
|---|---|---|---|---|
| 预设（测量的形状，p = 1.286） | SC π/2-BPSK / QPSK / 16-QAM / 64-QAM | 0 / 0 / 1.26 / 1.47 | 0 / 0.36 / 3.27 / 3.63 | 1.27 / 2.49 / 5.47 / 5.89 |
| | OFDM QPSK / 16-QAM / 64-QAM | 3.37 / 3.34 / 3.37 | 6.08 / 5.96 / 6.05 | 8.64 / 8.44 / 8.58 |
| TGad EM（p = 0.81） | SC π/2-BPSK / QPSK / 16-QAM / 64-QAM | 0 / 0 / 1.82 / 2.05 | 0 / 0.62 / 4.77 / 5.20 | 2.03 / 3.63 / 7.86 / 8.35 |
| | OFDM QPSK / 16-QAM / 64-QAM | 4.46 / 4.42 / 4.46 | 8.10 / 7.98 / 8.07 | 11.46 / 11.28 / 11.41 |

- 同一星座（16-QAM）SC 比 OFDM 少退 2.7 dB（预设 PA）/ 3.2 dB（TGad EM），与 1e-3 处的 PAPR 差 2.9 dB 一致。ROADMAP 原写的"SC 的 PAPR 低 3–4 dB"对 QPSK / π/2-BPSK 成立（4.1 / 6.4 dB），对 16 / 64-QAM 是 2.6–2.9 dB——验收线"≥ 3 dB"要写明星座与滚降。
- OFDM 的回退与星座无关（包络是高斯的）；SC 的回退随星座涨。所以 SC 换来的 EIRP 是"低阶星座上多、高阶上少"，要和它丢掉的频谱效率一起算，这一步等 ay 的 MCS 表。
- 0 dB 的格是"在饱和处就已经达标"（π/2-BPSK 几乎恒包络，压缩只是一个公共增益）。
- 滚降不在标准里（只有频谱模板），建 ay 行时它是 `assumed` 条目，带灵敏度行。

### 坑：训练场的峰值也过 PA（contains: 训练场 PAPR、全 1 训练）
- 全 1 的训练值在时域是一个冲激，PAPR = 使用音数（169 音即 22 dB），过 PA 被削，信道估计整体歪掉：同一回退上读数差 10 dB（2026-11-16 第一次量时踩到）。
- 换成随机 ±1 之后，OFDM 到 −20 dB 的回退随训练值的种子差 1.5 dB（8.45 对 6.97）：训练符号自己的峰值在削。所以 PA 隔离读法给 `receive(h=)` 不带训练场；真实帧里训练场（ay 的 CEF）怎么过 PA 是链路口径要单独算的一项——11ad / ay 的前导是单载波 Golay 序列，PAPR 低，所以这一项在真实帧里应当小，等数字到了实测。

## 4. 第一段接线（2026-11-16，feat/ay-wiring；示例 15）

**接法**：`config.WAVEFORMS_BUILT` 四种都在；`LinkSim(cfg)` 遇到 `ay_ofdm` / `ay_sc` 交给 `sim/ay_link.AyLinkSim`。前端模型、前端实例、信道、CFO、相噪、SNR 口径与 be 的链路共用，只换帧和接收机。
- 只在拓扑 B、EDMG 信道中心、K = 1 上；配置拒绝其余组合。数字学、MCS、EVM 限值、速率都从 spec 读（`ay/edmg.py`）。
- 预设 `config.ay_60ghz(waveform, mcs)` 建在 `zero_if_60ghz(k=1)` 上，前端设置与 be 预设逐字段相同。
- 两种波形跑在同一条链上（`assumed.ay_chain_rate`）：OFDM 2.64 GS/s × 2 = SC 1.76 Gchip/s × 3 = 5.28 GS/s，滤波器按 2.16 GHz 信道间隔建。
- 帧（`assumed.ay_preamble`）：STF 是 128 点 Golay × 16，CEF 是一对 Golay，各带一段 GI 长的循环前缀，后面是载荷。SC 用 RRC 0.25 成形（`assumed.ay_sc_pulse`）。
- 接收机（`assumed.ay_receiver`）：
  - STF 用 lag 128 自相关估 CFO（范围 ±fs/256）；
  - 用 CEF 那一对估信道，冲激响应截在 GI 内；
  - SC 用 MMSE 频域均衡，相位在每块前后两段 GI 之间线性插值；
  - OFDM 用 ZF，逐符号用 16 个导频去公共相位。
- 载荷不编码（`assumed.ay_evm_payload`）。
- SNR 定义：SC 按每码片、OFDM 按每有效子载波的 in-band SNR，与 be 同一口径。理想链在 20 dB 上读 −19.7 / −19.2 dB。

**示例 15 量到的**（信道 2，普通 GI，预设前端，flat 信道，不加噪声）：
- **PAPR**（载荷，1e-3）：OFDM 8.29–8.45 dB。SC 在滚降 0.25 时，π/2-BPSK 1.89、π/2-QPSK 4.16、π/2-16-QAM 5.49、π/2-64-QAM 5.71 dB。低阶差 ≥ 3 dB，验收线成立。
- **单开各项**（预设回退 7.5 dB，SC 载荷 64-QAM / OFDM 16-QAM）：

  | 损伤 | SC | OFDM |
  |---|---|---|
  | 理想链 | −49.9 | −36.9 |
  | PA | −28.4 | −21.7 |
  | 相噪 | −27.5（每块只取一个相位：−25.1） | −27.7 |
  | 转换器 | −41.8 | −35.6 |
  | 未校准的 IQ | −5.1 | −4.0 |
  | 未校准的 TX LO 泄漏，不加 CFO | 无影响 | 无影响 |
  | 未校准的 TX LO 泄漏 + CFO | −24.5 | −32.1 |

  IQ 失配在 be 的 2.56 GHz 行上一样大（原始链 −4.6 dB），要靠校准。
  TX LO 泄漏只有带着 CFO 才进来：接收端在安静前导上量 DC 并减掉，没有 CFO 时减得干净；有 CFO 时泄漏旋转着到，前导上平均掉，CFO 校正后又回到 DC。OFDM 那里是空的 DC 音，SC 那里是每个码片。
- **全开的底板与合规上限**（预设回退）：
  - 原始链：SC −8.1 … −8.2、OFDM −6.4 … −6.6 dB。上限 SC MCS2、OFDM 无。
  - 把 IQ 与 LO 泄漏当作校准掉：SC −24.3 … −25.5、OFDM −20.9 … −21.0 dB。上限 SC MCS16（π/2-16-QAM 7/8，5.39 Gb/s）、OFDM MCS15（16-QAM 7/8，5.11 Gb/s）。
- **同调制、同码率、各按自己的 EVM 限值**：SC 少退 0.36–0.68 dB（16-QAM 1/2 … 7/8、64-QAM 1/2），速率高 5.6 %（1.54 对 1.46 G 符号/s）。64-QAM 5/8 两边持平；3/4 起 SC 要多退 4.15 dB 或够不到。SC 的限值比 OFDM 严 3–4 dB（同为 16-QAM 1/2，−19 对 −15 dB），2.8 dB 的 PAPR 优势大部分被它吃掉。
- **每个 PA 输出功率上的最好速率**（单天线，EVM 口径）：回退 ≤ 8 dB（Pout ≥ 6.6 dBm）时 SC 高。例如 13.6 dBm 上 2.70 对 0.91 Gb/s，8.6 dBm 上 5.39 对 4.74 Gb/s。回退 ≥ 9 dB 时 OFDM 高（6.57–7.66 对 5.78–6.93 Gb/s）。原因是 SC 的底板停在约 −27 dB（相噪），够不到 64-QAM 13/16、7/8 的 −28 / −29 dB；OFDM 的 −25 / −27 dB 够得到。
- **一句话**：单天线、同一颗 PA，要输出功率（距离）就用 SC，要峰值速率就用 OFDM。SC 的回退优势在同调制同码率上只剩 0.4–0.7 dB，因为标准对 SC 的 EVM 要求更严。

**被推翻的判断**（`cairn/LOG.md` 2026-11-16）：
1. ROADMAP 原写的"SC 用回退换来的 EIRP，够不够抵掉丢掉的频谱效率"有前提错误。同调制同码率时 EDMG SC 的速率比 OFDM 高 5.6 %，丢的不是频谱效率。真正的代价是 SC 更严的 EVM 限值，以及更低的相噪底板。
2. 铁律 3 原写的"ay 靠 5.16 MHz SCS 本身"不成立。2.42 MHz 是 0.47 个子载波，不估计时两种波形都坏（EVM > −5 dB）；接住它的是 STF。

### 坑：OFDM 的理想链比 SC 差（contains: 理想链底板、GI）
- 理想链（无任何损伤）上 OFDM 只到 −35.7 … −37.9 dB，SC 到 −40 … −50 dB，随 GI 不单调。原因没查。离最严的限值（SC −29、OFDM −27 dB）还有 8 dB 以上，不影响上面的结论。

## 5. 第二段 2a：在 ay 的链上真跑校准（2026-11-16，feat/ay-stage2；示例 15 §7–§8）

**接法**：
- `calcheck.run_cal_ay(fe, cfg)` 在 ay 的链（2.16 GHz、5.28 GS/s）上跑 wifitrx 的序列（铁律 4）。
- 序列要的评分波形是 `assumed.ay_cal_probe`：11be 80 MHz × 22，过采样 3，占 1.71 GHz。2.16 GHz 配 5.28 GS/s 不是整数倍，所以借一个落在链通带里的标准波形。
- 链自己的步骤按链的参数走：LPF 角频按 `fc_nominal_hz`，IQ 的 FIR 按 `bandwidth_hz`。探针只用于快照、终检和 DPD 训练。
- 先在探针上把 PA 修到预设回退（Psat − 7.5 dB）再跑，不带 DPD，和 be 的行一样。
- `LinkSim(cfg, frontend=fe, chains=run.chains[:2])` 在校准过的链上跑 ay 波形。只校准一次；换回退时只重修驱动，和实际用法一致。
  （更正，第二段 2b：换回退时只重修驱动不行，TX LO 泄漏的抵消只对校准时的增益状态成立，见下面的坑。扫回退时每个点各校一次；同台表只在预设回退上读，一次就够。）

**校准步骤**（示例 15 §7）：

| 步骤 | 状态 | 读数 |
|---|---|---|
| TX LPF 角频 | 正常 | 误差 0 % |
| RX LPF 角频 | 退化 | 误差 6.38 % |
| RX DC | 正常 | −57.8 dBFS |
| TX LO 泄漏残差 | 退化 | −38.1 dBc |
| 回环延迟 | 正常 | 6.76 ns |
| TX IQ | 退化 | IRR 43.6 dB |
| 群时延 | 正常 | 5.05 ps |
| RX IQ | 退化 | IRR 44.0 dB |
| 终检 | 正常 | modem 读法 −21.3 dB（TX −21.5、RX −29.0）；isolation 读法 −7.65 dB |

isolation 读法只有 −7.65 dB，是 ROADMAP D5 那个宽带捕获对齐的偏差。2.56 GHz 的 be 列是 −13.5 对 modem −23.4 dB，同一个现象。和 be 的 2.56 GHz 列（IRR 40.2 dB、泄漏 −39.8 dBc、RX 角频 8.7 %）同一个量级，2.16 GHz 略好。

**校准过的链上**（示例 15 §8，预设回退，flat，不加噪声）：
- **底板**：SC −24.0 … −25.1 dB，OFDM −20.9 … −21.0 dB。原始链是 −6.4 … −8.2 dB。第一段“IQ 与 LO 泄漏当作校准掉”给的是 SC −24.3 … −25.5、OFDM −20.9 … −21.0 dB：OFDM 一样，SC 差 0.3–0.4 dB。
- **合规上限不变**：SC MCS16（5.39 Gb/s），OFDM MCS15（5.11 Gb/s）。
- **同调制同码率的回退**（每个回退点各跑一次校准）：
  - SC 少退 0.14–0.32 dB（16-QAM 1/2 … 7/8），64-QAM 1/2 少退 0.07 dB，64-QAM 5/8 多退 0.55 dB；
  - SC 的 64-QAM 3/4 以上在回退 15 dB 内够不到；OFDM 64-QAM 7/8 在 12.92 dB 够到。
  - **更正（2026-11-16，第二段 2b）**：这一条最初（#51）读的是只在预设回退校准一次、换回退只重修驱动的链，得 SC 少退 0.01–0.15 dB、64-QAM 5/8 多退 0.34 dB、OFDM 64-QAM 7/8 够不到。那是假象，见下面的坑。
- **SC 在校准过的链上多出来的损失**：每个回退点各校一次后，SC 比“当作校准掉”多 0.2–0.8 dB（回退 5 / 7.5 / 10 / 12.5 / 15 dB 时 +0.45 / +0.38 / +0.21 / +0.44 / +0.78），OFDM 在 ±0.07 dB 内。原因没完全找到：
  - 已排除：带着 CFO 进来的残余 LO 泄漏（关掉 CFO，SC 校准链 −24.28、当作校准掉 −24.84 dB，差不变）；探针外推带边的 IQ 校正（滚降 0.10 / 0.25 / 0.40，带边 ±0.97 / ±1.10 / ±1.23 GHz，差 0.31 / 0.38 / 0.40 dB）。
  - 把校准链的非 IQ 状态逐项搬到干净链上量：RX LPF 调谐码约 0.13 dB，TX 侧的校准状态约 0.2 dB，其余（DC、相位 / 时延修正）为零；单次读数有约 0.1 dB 的散布，分不更细。
  （ROADMAP 里程碑 3）

### 坑：LO 泄漏的校准只在它那个增益状态成立（contains: 增益状态、dc_pre、单次校准、换回退）
- wifitrx 的 TX LO 泄漏步骤算出一个数字预抵消 `dc_pre`，它对的是校准时的 VGA。换回退要改 VGA（预设 7.5 dB 时 −3.2 dB，15 dB 时 −11.4 dB），抵消就对不上了，泄漏回来。
- 接收端在安静前导上量 DC 并减掉，所以没有 CFO 时看不出来；带着 CFO，泄漏旋转着到、在前导上平均掉，CFO 校正后又是 DC，压在每个 SC 码片上。
- 数（示例 15 §8 那一行，π/2-16-QAM）：在 7.5 dB 校准、跑在 15 dB，带 CFO −16.56 dB、不带 −26.09 dB；在 15 dB 重新校准 −26.41 dB。
- 所以在校准过的链上扫回退，每个点都要重新跑序列（真芯片按增益档各校一次）。`tests/test_ay_link.py::test_the_tx_lo_leak_calibration_holds_only_at_its_gain_state` 守着。

**更正（2026-11-16）**：§4 那句“同调制同码率时 SC 少退 0.36–0.68 dB”只在“IQ 与 LO 泄漏当作校准掉”的假设下成立。在真跑校准的链上只剩 0.01–0.15 dB，等于没有：SC 的 PAPR 优势被它严 3–4 dB 的 EVM 限值，加上 0.3–0.4 dB 的校准残差，全部抵掉。**再更正（第二段 2b）**：0.01–0.15 dB 是只校准一次的假象（上面的坑）；每个回退点各校一次后是 0.14–0.32 dB（16-QAM），仍比“当作校准掉”的 0.50–0.68 dB 小一半多，结论的方向不变：PAPR 优势大部分被更严的限值和 SC 自己的校准残差抵掉。剩下的只有 SC 快 5.6 % 的速率。§4 的一句话结论（单天线、同一颗 PA，要输出功率用 SC、要峰值速率用 OFDM）要按这个修正。低阶星座在大输出功率上 SC 仍占上风：§6 在小回退上 SC 2.70 对 OFDM 0.91 Gb/s，那一节没有在校准链上重算。

## 6. 第二段 2b：同台表两行（2026-11-16，feat/ay-stage2b-table；示例 04 §1b，`compare.evaluate_ay`）

- 拓扑 B 上两行，同一个前端实例；底板按载荷星座读时域 EVM，原始链与真跑过校准的链各一列（两行共用一次 `run_cal_ay`）。数和读法见 `comparison-table.md` §2c。
- **合规上限按 be 行的规则**：底板比限值低 `assumed.mcs_evm_margin_db`（3 dB）。这样 OFDM 是 MCS13（4377 Mb/s），SC 是 MCS14（4620 Mb/s），两行都停在 16-QAM 3/4。
  示例 15 读的是限值本身（不留余量），同一条链上是 OFDM MCS15、SC MCS16；表里旁边一列给这个读法。两种读法并存，不是矛盾：示例 15 问的是“这个波形离规范多远”，同台表问的是“各方案按同一规则能发什么”。
- **和 be 行比要在同一口径**：两边都取校准后的上限。be 行最快也最省的是 11be 80 MHz × 32（2.56 GHz）的 MCS2，3459 Mb/s、270 pJ/bit。ay 的 SC 行快 1.3 倍、每比特省 1.4 倍，不计解码器。
- 两边读法仍不对称：be 行的校准列是 IRR 查表加解析和，ay 行是校准链上的时域读数。ROADMAP A3 那条“`run_cal_at` 实跑进表”现在决定这个倍数。
- 敏感度一节（示例 04 §6）不含 ay 行，因为它们没有解析侧。`tools/budget_report.py` 多基准时，ay 两行只随第一个基准出现一次。

### 坑：两种上限读法（contains: 合规余量、mcs_evm_margin_db、口径错位）
- 第一版 ay 行用“底板 ≤ 限值”，与 be 行的 3 dB 余量不是同一规则，结果偏高两档：OFDM MCS15 / SC MCS16 对 MCS13 / MCS14。铁律 2 要求同一条规则，所以改了，旧读法留作旁列。
- 第一版拿 ay 行校准后的 pJ/bit 去比 be 行 §1 未校准的 pJ/bit（592，11be 80 MHz × 8），得到 3 倍。换成 be 行校准后的口径只有 1.4 倍。

## 7. 第二段 2b（下）：按功率换距离（2026-11-16，feat/ay-range；示例 15 §9）

**门限从哪来**（`assumed.ay_sensitivity`；`ay.edmg.dmg_twin`、`ideal_threshold_db`）：
- spec_sources 没有 EDMG 灵敏度。EDMG 某档若在 DMG 表里有同样每符号比特数、码率与重复的一档，就用那一档的最低灵敏度（`dmg.rx_sensitivity_dbm`）。
  - SC 对 `dmg.sc_mcs`，按调制阶数、码率、重复；OFDM 对 `dmg.ofdm_mcs`，按每子载波编码比特数与码率。EDMG 的 DCM BPSK / DCM QPSK 就是 11ad 的 SQPSK / QPSK（`edmg.ofdm_mcs` 的注释；测试核对了配上的名字）。
  - SC 有 12 档能配上（MCS 1–5、7–10、12–14），OFDM 也是 12 档（1、2、6–8、11–14、17–19）。
- 减去 kT·B（B 取占用带宽，与 ay 链路的带内 SNR 同一口径）和参考接收机的 10 dB NF、5 dB 实现损耗，得理想解码器的门限。实现损耗拿掉，因为本库把收发两侧的损伤读成 EVM 底板，再按噪声项加回去，与 be 行用实测门限的做法一致。
- 交叉核对：同调制同码率时，比本库实测的 11be LDPC 门限高 0.86–1.14 dB（OFDM），SC 的 16-QAM 3/4 高 2.27 dB。DMG 表自己就让 SC 比 OFDM 同档严 1 dB（16-QAM 3/4：−53 对 −54 dBm）。

**距离怎么算**（`arraylink.ay_mcs_ranges`，与 be 的 `array_budget` 同一套函数）：底板当噪声项加在门限上，共享前端的 NF（AGC 状态下）给出接收机输入，EIRP + G_rx 减去它是路径损耗，再按自由空间加氧吸收换成距离。每个回退点都在那个回退上真跑过校准的链上读底板（§8 的 `cal_at`）。发射机要满足该档的 TX EVM 限值（不留余量：热噪声已经单算）。
  这一条比示例 10 严：be 的距离按解码器上限算，不要求发射机合规。§9 问的是“该选哪个回退”，选到不合规的回退没有意义，所以加了这一条；SC MCS14 的最佳回退 5.0 dB 正是被它卡住的（底板 −21.32 对限值 −21 dB）。和 be 行放在同一张阵列表里时要用同一条规则（ROADMAP 里程碑 3 的阵列一项）。

**数**（单天线 0 dBi，预设的接收梯子 NF 3.5 dB，不是 60 GHz 的数，ROADMAP C9）：
- 预设回退（7.5 dB）：SC MCS14（16-QAM 3/4）1.43 m，OFDM MCS13 1.55 m、MCS14 1.35 m。OFDM 的 64-QAM 在预设回退上不满足 TX EVM 限值。
- 每档取射程最远的回退：SC MCS14 在 5.0 dB 到 1.82 m，OFDM MCS13 在 5.5 dB 到 1.77 m。16-QAM 的最佳回退比预设小 2–2.5 dB：预设的规则（PA 单独到 −21 dB）是按 EVM 定的，不是按距离定的。
- SC 的 π/2-BPSK / π/2-QPSK 各档最佳回退都落在网格最小的 1 dB 上（底板 −16.6 / −15.8 dB，离限值很远），真正的最佳可能更小。SC MCS1 到 17.17 m；OFDM MCS1 在 1 dB 上到 12.90 m。
- 每个距离上还能保住的最快速率（Gb/s）：

| 距离 | SC | OFDM |
|---|---|---|
| 1 m | 4.620（MCS14） | 4.742（MCS14） |
| 2 m | 3.850（MCS13） | 3.647（MCS12） |
| 3 m | 2.502（MCS10） | 2.918（MCS11） |
| 5 m | 2.502（MCS10） | 2.188（MCS8） |
| 8 m | 1.925（MCS8） | 1.459（MCS6） |

- 读法：近处两者相当，5 m 起 SC 领先。SC 的低阶星座能把回退压到 1 dB，多出 6.5 dB 输出功率，PAPR 优势在这里变成距离。前面几节同调制同码率的配对只比了 16-QAM 与 64-QAM，低阶星座没有比过。
- 灵敏度行（预设回退，同台表的两档上限）：实现损耗留着时 SC 0.73 / OFDM 0.70 m；换成查到的 60 GHz 前端（NF 6.1 dB、两端 2 dBi）时 1.68 / 1.82 m。

### 坑：配不上的档让表偏向一边（contains: DMG 对应档、扩展 MCS、射程表不对称）
- SC 的 16-QAM 13/16、7/8 和全部 64-QAM 没有 DMG 对应档，所以没有门限，不进距离表；OFDM 的 16-QAM 13/16 和 64-QAM 5/8–13/16 都有。所以 1 m 处 OFDM 4.742 对 SC 4.620 Gb/s 这一行的比较不成立：SC 的 MCS15 / 16 没有门限，算不出来。
- DMG 的扩展档 9.1、12.1–12.6 正好是这些（π/2-64QAM 到 8085 Mbps），但它们的调制与码率不在 spec_sources 里（`dmg.sc_mcs` 的注释），不能凭记忆配。要补，得请 spec_sources 读原文（ROADMAP 里程碑 3）。
