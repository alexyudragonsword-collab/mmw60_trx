**和 be 最好的一行比**（同一个前端、同一个阵列）：
- 阵列表（N = 64）：be 最好的是拓扑 B 的 11be 80 MHz × 4（320 MHz），MCS7、1441 Mb/s、289 m、3381 pJ/b。ay SC 的 16-QAM 3/4 是 4620 Mb/s、322 m：速率 3.2 倍，距离是它的 111 %，乘积 3.6 倍；取 SC 的上限是 8085 Mb/s、153 m、660 pJ/b，每比特少到 1/5.1。（2026-11-18 天线进预设之前（0 dBi）：be 那一行 MCS6、1297 Mb/s、304 m、4279 pJ/b，SC 277 m、速率 3.6 倍、距离 91 %、乘积 3.2 倍、上限 127 m / 743 pJ/b、1/5.8——be 那一行在 N = 64 上多了一档，速率的倍数小了，上限那一档的距离短了；2026-11-18 换接收前端之前 368 m、337 m、92 %、3.3 倍、161 m。）
- 同台表（单天线、校准后的合规上限）：be 最快也最省的是 11be 80 MHz × 32（2.56 GHz）的 MCS2，3459 Mb/s、272 pJ/bit；ay SC 4620 Mb/s、189 pJ/bit，快 1.3 倍、省 1.4 倍（OFDM 4742 / 188，1.4 倍、1.4 倍）。
- 这两个倍数要带着口径读：ay 行的 pJ/bit 不计解码器（be 行计，272 里占 14）；be 行的校准列是 IRR 查表加解析和，ay 行是校准链上的时域读数（`comparison-table.md` §2c）。

**前提**（结论只在这些前提下成立）：
- 单信道（2.16 GHz，信道 2，60.48 GHz），单流；拓扑 B 的硬件，两种波形共用一个 `Frontend60` 实例、一条 5.28 GS/s 的链、同一次校准（铁律 2、4）。
- PA 是预设的（测量的形状，回退 7.5 dB，不带 DPD）；接收前端是预设的（2026-11-18 起是一颗 60 GHz 通信收发机的数：增益 27 dB、NF 6.1 dB、IIP3 −20 dBm，`assumed.preset_rx_front`，ROADMAP C9），天线是同一颗收发机的封装内天线 2 dBi（同日稍后进预设，`assumed.preset_antenna`；收发同一副，阵列上是每个单元的增益——这样并是本库的选择）。梯子其余七档的形状仍是假设。0 dBi 的天线（`config.unspecified_antenna`，之前的预设）下单天线的距离是现在的 0.63 倍（16-QAM 3/4：SC 1.99 → 1.26 m）。
  （2026-11-18 之前这里写：“接收梯子是 WiFi 7 的，NF 3.5 dB，**不是 60 GHz 的数**（ROADMAP C9，下一步）。换成查到的 60 GHz 前端距离都变，SC 对 OFDM 的比不变。”换了之后确实如此：每个距离短 26 %（单天线，自由空间）到 13–21 %（N = 64，氧吸收占一部分：MCS1 669 对 765 m，解码器上限 127 对 161 m），两种波形同比例。）
- 门限是本库接收机在理想链、flat 信道上量的（`ay_per_thresholds.yaml`），不是规范数；OFDM 的门限比 SC 同调制同码率高 0.07–0.34 dB（§9e），这已经在上面的数里。距离是自由空间加 15 dB/km 的氧吸收（估算），视距。
- 多径一列 SC 是量的，OFDM 是一个 assumed 余量；高阶上偏向 OFDM（§9f）。
- 线性化引擎：带外、杂散、模板不背书（铁律 6）。最慢一档“最佳回退”的距离压在 PA 的极限上，是上界。

**被推翻的预期**（都留在正文里，这里列出来）：
- **“SC 的低 PAPR 换成回退”——同调制同码率下只换来 0.2–0.4 dB**。16-QAM 上 SC 的 PAPR 比 OFDM 低 2.8 dB，但 SC 同调制同码率的 TX EVM 限值严 3–4 dB，几乎全吃掉：SC 少退 0.30–0.45 dB（当作校准掉）、0.20–0.32 dB（校准链），64-QAM 5/8 反而多退 0.32 dB，3/4 起够不到（§4、§5；2026-11-18 换接收前端之前 0.29–0.43、0.21–0.34、0.25：校准经接收机观测，读数动了百分之几 dB）。最早读到的 0.01–0.15 dB 是只在预设回退校准一次的假象。PAPR 真变成东西的地方是低阶档（BPSK 能压到 PA 的极限，多出 7.5 dB 输出）和阵列（少 13 个单元）。
- **“SC 的回退余量变成更少的直流功率”**：顶到 EIRP 上限时 PA 的直流功率与工作点几乎无关（2639–2644 mW）；省下的是单元和移相器（§8）。
- **“OFDM 比 SC 差 0.4–1.7 dB 是波形的事”**：大半是本库接收机的——训练场、逐符号的导频相位、解映射各音同权；改掉后剩 0.07–0.34 dB（§9e）。
- **“多径余量 0.8–0.9 dB”**：那是 EVM 口径；PER 门限的代价随调制阶数从 0.3 涨到 1.6 dB（§9f）。
- **“孪生规则（借 DMG 灵敏度）对 OFDM 偏悲观”**：实测下来对 OFDM 偏乐观，对 SC 的高阶档偏悲观 1.4–4.3 dB（§9d）。

**剩下的**：外部阻塞四条、按需九条，在 ROADMAP 里程碑 3；都不动上面的结论，除了一条——OFDM 的交织置换到了之后，多径一列要重量。

## 1. 范围（用户 2026-11-16 定）

- ay 不是第三条拓扑：拓扑 B 的硬件（零中频链、同一前端实例）配第三、四种波形 `ay_ofdm` / `ay_sc`。
- 数字（EDMG OFDM / SC 单信道数字学、MCS 表、DMG / EDMG 的 TX EVM 限值、灵敏度表）只从 spec_sources 进来（铁律 5）。已发 spec_sources#29，本库是发起方，合并后由本库验收并关。2026-11-16 已回（spec_sources#30，pin `3123b65`；键见 `cairn/spec-sources.md`），EDMG 灵敏度没有出处。
- 第一轮只做 EVM 口径（不做编码 PER），只做单信道（不做 2 / 3 / 4 信道绑定）。
- 数字到之前先建与数字无关的部分；`config.WAVEFORMS_BUILT` 不含 ay，`LinkSim` 照样拒绝（`tests/test_laws.py::test_law1_waveform_enum_is_complete_and_ay_refuses`）。

## 2. 骨架（`src/mmw60/ay/`，2026-11-16）

每个模块都把数字学当参数，测试用的是合成数字学（2 的幂、1 GS/s），`tests/test_ay_skeleton.py`。

| 模块 | 内容 | 测试守的 |
|---|---|---|
| `golay.py` | 由延迟向量 D 与权向量 W 递推出 Golay 互补对（802.11ad 写 Ga / Gb 的同一形式；用哪组 D / W 是规范数字） | 任意 D 排列、W ∈ {±1, ±j} 下互补；非法 D / W 报错 |
| `sc.py` | 单载波块：[G \| d₀ \| G \| d₁ \| … \| G]，窗口 [d_b \| G] 前面的 G 就是循环前缀；可选逐样本旋转 e^{jrn}（π/2-BPSK 一族），要求 r·block 是 2π 的整数倍，否则拒绝；互补对各带一段循环前缀做信道估计（DMG CEF 的原理，不是它的布局）；ZF / 去偏 MMSE 频域均衡；用尾部已知 G 逐块跟公共相位 | 信道不长于 G 时估计与 ZF 都精确到数值精度，长于 G 时有块间干扰；flat 信道上 MMSE 读出 SNR（±0.3 dB）且无偏；相位漂移被尾 G 跟住 |
| `ofdm.py` | 任意子载波排布（FFT 点数、CP、采样率、数据 / 导频的有符号索引、导频值）；训练符号估信道、ZF、导频去公共相位；`receive(h=)` 给定信道（PA 隔离读法） | 多径不长于 CP 时精确；逐符号随机公共相位被导频去掉 |
| `papr.py` | 理想插值 / 抽取、根升余弦成形与匹配滤波、PAPR CCDF、`obo_for_evm`（共享 PA 上 EVM 到目标所需的回退） | 往返透明；多音 OFDM 的 1e-3 处 PAPR 是高斯包络的 8.39 dB（±0.3）；回退差约等于 PAPR 差 |

CFO：重复一段长 L 的序列，`rx.cfo.stf_coarse_cfo` 以 L 为滞后估计，范围 ±fs/(2L)，越界按 fs/L 混叠（测试守）。ay 的 L-STF 用哪段序列、重复几次是规范数字。

- 同一星座（16-QAM）SC 比 OFDM 少退 2.7 dB（预设 PA）/ 3.2 dB（TGad EM），与 1e-3 处的 PAPR 差 2.9 dB 一致。ROADMAP 原写的"SC 的 PAPR 低 3–4 dB"对 QPSK / π/2-BPSK 成立（4.1 / 6.4 dB），对 16 / 64-QAM 是 2.6–2.9 dB——验收线"≥ 3 dB"要写明星座与滚降。
- OFDM 的回退与星座无关（包络是高斯的）；SC 的回退随星座涨。所以 SC 换来的 EIRP 是"低阶星座上多、高阶上少"，要和它丢掉的频谱效率一起算，这一步等 ay 的 MCS 表。
- 0 dB 的格是"在饱和处就已经达标"（π/2-BPSK 几乎恒包络，压缩只是一个公共增益）。
- 滚降不在标准里（只有频谱模板），建 ay 行时它是 `assumed` 条目，带灵敏度行。

### 坑：训练场的峰值也过 PA（contains: 训练场 PAPR、全 1 训练）
- 全 1 的训练值在时域是一个冲激，PAPR = 使用音数（169 音即 22 dB），过 PA 被削，信道估计整体歪掉：同一回退上读数差 10 dB（2026-11-16 第一次量时踩到）。
- 换成随机 ±1 之后，OFDM 到 −20 dB 的回退随训练值的种子差 1.5 dB（8.45 对 6.97）：训练符号自己的峰值在削。所以 PA 隔离读法给 `receive(h=)` 不带训练场；真实帧里训练场（ay 的 CEF）怎么过 PA 是链路口径要单独算的一项——11ad / ay 的前导是单载波 Golay 序列，PAPR 低，所以这一项在真实帧里应当小，等数字到了实测。

## 4. 第一段接线（2026-11-16，feat/ay-wiring；示例 15）

**接法**：`config.WAVEFORMS_BUILT` 四种都在；`LinkSim(cfg)` 遇到 `ay_ofdm` / `ay_sc` 交给 `sim/ay_link.AyLinkSim`。前端模型、前端实例、信道、CFO、相噪、SNR 口径与 be 的链路共用，只换帧和接收机。
- 只在拓扑 B、EDMG 信道中心、K = 1 上；配置拒绝其余组合。数字学、MCS、EVM 限值、速率都从 spec 读（`ay/edmg.py`）。
- 预设 `config.ay_60ghz(waveform, mcs)` 建在 `zero_if_60ghz(k=1)` 上，前端设置与 be 预设逐字段相同。
- 两种波形跑在同一条链上（`assumed.ay_chain_rate`）：OFDM 2.64 GS/s × 2 = SC 1.76 Gchip/s × 3 = 5.28 GS/s，滤波器按 2.16 GHz 信道间隔建。
- 帧（`assumed.ay_preamble`）：STF 是 128 点 Golay × 16，CEF 是一对 Golay，各带一段 GI 长的循环前缀，后面是载荷。SC 用 RRC 0.25 成形（`assumed.ay_sc_pulse`）。
  （2026-11-18 更正：这是 SC 的帧，也是 OFDM 到那天为止的帧。OFDM 现在发规范的 EDMG-STF 与 EDMG-CEF，见 §9e。）
- 接收机（`assumed.ay_receiver`）：
  - STF 用 lag 128 自相关估 CFO（范围 ±fs/256）；
  - 用 CEF 那一对估信道，冲激响应截在 GI 内；
  - SC 用 MMSE 频域均衡，相位在每块前后两段 GI 之间线性插值；
  - OFDM 用 ZF，逐符号用 16 个导频去公共相位。
    （2026-11-18 更正：OFDM 的信道在 EDMG-CEF 上估，公共相位跨 17 个符号合并，见 §9e。）
- 载荷不编码（`assumed.ay_evm_payload`）。
- SNR 定义：SC 按每码片、OFDM 按每有效子载波的 in-band SNR，与 be 同一口径。理想链在 20 dB 上读 −19.7 / −19.2 dB。

  | 未校准的 TX LO 泄漏 + CFO | −24.5 | −34.5 |

  （OFDM 一列2026-11-18 OFDM 接收机改动（§9e）之前依次是 −36.9 / −21.7 / −27.7 / −35.6 / −4.0 / 无影响 / −32.1。未校准的 IQ 一行两个读数都是不通的链：原先 Golay 对的镜像与序列自己对齐，进估计的是一个公共偏差；EDMG-CEF 的 conj(C₋ₖ)/Cₖ 在 ±1、±j 之间近乎随机，镜像进估计成了逐音的起伏，拟合留下其中 23 %，读数更差。校准后镜像在 −44 dB，这一项看不见，见校准链的底板。）

  IQ 失配在 be 的 2.56 GHz 行上一样大（原始链 −4.6 dB），要靠校准。
  TX LO 泄漏只有带着 CFO 才进来：接收端在安静前导上量 DC 并减掉，没有 CFO 时减得干净；有 CFO 时泄漏旋转着到，前导上平均掉，CFO 校正后又回到 DC。OFDM 那里是空的 DC 音，SC 那里是每个码片。
- **全开的底板与合规上限**（预设回退）：
  - 原始链：SC −8.1 … −8.2、OFDM −7.5 dB。上限 SC MCS2、OFDM MCS1。（2026-11-18 OFDM 接收机改动（§9e）之前 OFDM −6.4 … −6.6 dB、无上限。）
  - 把 IQ 与 LO 泄漏当作校准掉：SC −24.3 … −25.5、OFDM −21.0 dB（之前 −20.9 … −21.0）。上限 SC MCS16（π/2-16-QAM 7/8，5.39 Gb/s）、OFDM MCS15（16-QAM 7/8，5.11 Gb/s）。
- **同调制、同码率、各按自己的 EVM 限值**：SC 少退 0.30–0.45 dB（16-QAM 1/2 … 7/8、64-QAM 1/2），速率高 5.6 %（1.54 对 1.46 G 符号/s）。64-QAM 5/8 两边持平（差 0.12 dB）；3/4 起 SC 要多退 3.73 dB 或够不到。（2026-11-18 预设换成 60 GHz 接收前端之前 0.29–0.43、0.09、4.01 dB：底板经接收机读，动了 0.01–0.04 dB，64-QAM 3/4 那一档在 SC 底板的平坡上，0.03 dB 的底板就是 0.28 dB 的回退。2026-11-18 OFDM 接收机改动（§9e）之前：SC 少退 0.36–0.68 dB，3/4 多退 4.15 dB。）SC 的限值比 OFDM 严 3–4 dB（同为 16-QAM 1/2，−19 对 −15 dB），2.8 dB 的 PAPR 优势大部分被它吃掉。
- **每个 PA 输出功率上的最好速率**（单天线，EVM 口径）：回退 ≤ 8 dB（Pout ≥ 6.6 dBm）时 SC 高。例如 13.6 dBm 上 2.70 对 1.46 Gb/s，8.6 dBm 上 5.39 对 4.74 Gb/s。（2026-11-18 OFDM 接收机改动（§9e）之前 13.6 dBm 上 OFDM 是 0.91 Gb/s。）回退 ≥ 9 dB 时 OFDM 高（6.57–7.66 对 5.78–6.93 Gb/s）。原因是 SC 的底板停在约 −27 dB（相噪），够不到 64-QAM 13/16、7/8 的 −28 / −29 dB；OFDM 的 −25 / −27 dB 够得到。
- **一句话**：单天线、同一颗 PA，要输出功率（距离）就用 SC，要峰值速率就用 OFDM。SC 的回退优势在同调制同码率上只剩 0.4–0.7 dB，因为标准对 SC 的 EVM 要求更严。

**被推翻的判断**（`cairn/LOG.md` 2026-11-16）：
1. ROADMAP 原写的"SC 用回退换来的 EIRP，够不够抵掉丢掉的频谱效率"有前提错误。同调制同码率时 EDMG SC 的速率比 OFDM 高 5.6 %，丢的不是频谱效率。真正的代价是 SC 更严的 EVM 限值，以及更低的相噪底板。
2. 铁律 3 原写的"ay 靠 5.16 MHz SCS 本身"不成立。2.42 MHz 是 0.47 个子载波，不估计时两种波形都坏（EVM > −5 dB）；接住它的是 STF。

### 坑：OFDM 的理想链比 SC 差（contains: 理想链底板、GI）
- 理想链（无任何损伤）上 OFDM 只到 −35.7 … −37.9 dB，SC 到 −40 … −50 dB，随 GI 不单调。原因没查。离最严的限值（SC −29、OFDM −27 dB）还有 8 dB 以上，不影响上面的结论。

## 7. 第二段 2b（下）：按功率换距离（2026-11-16，feat/ay-range；示例 15 §9）

**门限从哪来**（2026-11-16 起 SC 用本库实测的门限，§9d；下面的孪生规则 `assumed.ay_sensitivity` 管 OFDM 与 SC MCS 1，也是 `rule="twin"` 的读法——2026-11-17 起两种波形每档都是实测，孪生规则只剩 `rule="twin"` 的灵敏度读法；`ay.edmg.threshold_db`、`dmg_twin`、`ideal_threshold_db`）：
- spec_sources 没有 EDMG 灵敏度。EDMG 某档若在 DMG 表里有同样每符号比特数、码率与重复的一档，就用那一档的最低灵敏度（`dmg.rx_sensitivity_dbm`）。
  - SC 对 `dmg.sc_mcs`，按调制阶数、码率、重复；OFDM 对 `dmg.ofdm_mcs`，按每子载波编码比特数与码率。EDMG 的 DCM BPSK / DCM QPSK 就是 11ad 的 SQPSK / QPSK（`edmg.ofdm_mcs` 的注释；测试核对了配上的名字）。
  - SC 有 12 档能配上（MCS 1–5、7–10、12–14），OFDM 也是 12 档（1、2、6–8、11–14、17–19）。spec_sources#33 之后 SC 又配上扩展档 9.1、12.1–12.6（MCS 11、15、16、18–21），只剩 BPSK 7/8 与 64-QAM 1/2 配不上。
- 减去 kT·B（B 取占用带宽，与 ay 链路的带内 SNR 同一口径）和参考接收机的 10 dB NF、5 dB 实现损耗，得理想解码器的门限。实现损耗拿掉，因为本库把收发两侧的损伤读成 EVM 底板，再按噪声项加回去，与 be 行用实测门限的做法一致。
- 交叉核对：同调制同码率时，比本库实测的 11be LDPC 门限高 0.86–1.14 dB（OFDM），SC 的 16-QAM 3/4 高 2.27 dB。DMG 表自己就让 SC 比 OFDM 同档严 1 dB（16-QAM 3/4：−53 对 −54 dBm）。

  这一条比示例 10 严：be 的距离按解码器上限算，不要求发射机合规。§9 问的是“该选哪个回退”，选到不合规的回退没有意义，所以加了这一条；SC MCS14 的最佳回退 5.0 dB 正是被它卡住的（底板 −21.32 对限值 −21 dB）。和 be 行放在同一张阵列表里时要用同一条规则（ROADMAP 里程碑 3 的阵列一项）。

### 坑：隔离时先关 PA 再建链，读出来的泄漏是假的（contains: VGA、隔离读法、dc_pre）

### 9d. 编码 PER：DMG / EDMG 的码与实测门限（`ay/coding.py`，feat/ay-coded → feat/ay-33-keys）
- **已建**：`phy.ldpc.qc_code` 能从任意基矩阵与提升因子构造准循环码（802.11 的码改走它，边数组逐位相同；DMG / EDMG 的是 16 列、z = 42）。SC 载荷装整数个码字，不够一个码字的比特用随机填充，接收端丢掉。接收端从均衡后的码片求 max-log LLR，不做逐码片加权：SC 的 MMSE 让每个码片 SINR 相同，归一化 min-sum 又对 LLR 的整体缩放不敏感。任一码字的任一信息比特错就算丢包。`AyLinkSim.transmit(rng, bits=)` 接收载荷比特（只对 SC）。
- **替身验证**：用 802.11 的 648 码（码率 1/2）、π/2-QPSK、行为模型的理想链：不加噪声时零错，−3 dB 全丢，6 dB 全对；把 LLR 的符号翻过来测试就变红（`test_the_coded_sc_path_with_an_80211_code_standing_in`）。替身码的 PER 曲线不打印：它不是 EDMG 的码，打出来容易被当成 EDMG 的数。
- **码（2026-11-16，spec_sources#33，铁律 5）**：`coding.dmg_code` 从 `dmg.ldpc_matrices` 提升四个码率（1/2、5/8、3/4、13/16，672 位，z = 42）；DMG 的 7/8 是 13/16 码字不发前 48 个校验位（`dmg.ldpc_r7_8_punctured`，624 / 546，`PuncturedCode`：收端在那 48 位填零 LLR）。`coding.edmg_code` 在 7/8 用 EDMG 自己的 672 位码（`edmg.ldpc_672_r7_8`，588 位信息；大多数格是两个移位单位阵之和，`qc_code` 为此接受一格多个移位，相等的移位在 GF(2) 上相消，拒收）。spec_sources 的交叉核对在本库复现：EDMG 7/8 的校验阵就是 DMG 3/4 的第 1+3、2+4 块行之和，逐位相同。每个码编出来校验子为零、干净码字解得回（`test_the_dmg_and_edmg_codes_are_spec_sources_matrices_and_agree_with_each_other`）。`PendingSpec` 删掉了。

### 9e. OFDM 接收机：EDMG-CEF、跨符号相位、按估计加权的 LLR（2026-11-18，feat/ay-ofdm-receiver）
里程碑 3 收尾里唯一会改结论的一件。原来 OFDM 的实测门限比 SC 同调制同码率高 0.42–1.69 dB（§9d），其中多少是本库接收机自己的，决定了 SC 对 OFDM 的比较站不站得住。做了三项，分开量、再合起来量；预期都先写进诊断脚本再跑（`tools/diag_ay_ofdm_receiver.py`、`tools/diag_ay_ofdm_low_snr.py`），对不上的查了原因，没有调参数。

**(a) 训练场用规范的**（`ay/training.py`，spec_sources#48，pin `65ff5e4`）：
- 原计划是 DMG 的混合速率前导（1.76 GHz 单载波再重采样到 2.64 GHz）。对方的答复改了做法：**EDMG OFDM 包的数据信道用 EDMG-CEF 估**，1.76 GHz 的 L-CEF 只管两个头。于是建的是 EDMG-STF（88 个音、周期 128 点、30 个周期）与 EDMG-CEF（352 个音上同一条单位模序列发 2 个符号、第 2 个取负，各带长 GI 192 点）。两个场的 PAPR 都是 3.0 dB。CFO 在 EDMG-STF 上估，周期与原来一样是 128 点，范围不变。
- **换训练场本身不省噪声**。352 个音上是全部能量，但响应只在 512 个 bin 里的 352 个上看得到；把 108 个窗内抽头（GI 加 GI/8）精确地最小二乘拟合到这些音上，留下 108/352 的噪声，(108/352)/2 = 0.153，正是原来 2.64 GHz 上 Golay 对的数。省的在估计器：108 个抽头透过 69 % 的带宽只张成约 74 个方向（奇异值从第 75 个的 0.65 掉到第 85 个的 7e-5），拟合只留最大值 1e-3 以上的 82 个（`assumed.ay_receiver` 的 `ofdm_ce_rcond`），估计噪声 0.1165，0.48 dB，原来 0.62 dB。门槛取 1e-1 / 1e-3 / 1e-6 时留 78 / 82 / 88 个方向、丢 0.52 / 0.54 / 0.58 dB：结果不靠这个数。
- **带边单独报**（估计噪声相对一个数据音的噪声，实测 | 拟合的投影算子）：均值 0.1159 | 0.1165；带中 0.92 | 0.94 倍均值；两边各 8 个音 1.86 | 1.85 倍；最外一个音 4.4 | 4.0 倍；DC 空隙两侧的 k = ±2 各 1.65 倍。原来 Golay 对的估计各音一样（实测带边 0.93 倍）。

  | OFDM MCS 1，按估计加权（现在） | +0.05 | +0.29 |

- 读法：CFO 估计与相位跟踪不花代价；差全在信道估计上，而且 PER 曲线拖一条尾巴（0.5 / 1.0 / 1.5 dB 上 13/200、45/3000、22/3000，SC 半个 dB 内从 60/2089 掉到 1/3000）。尾巴是每包一次的事件，每包只抽一次的只有信道估计：1 dB 上它的误差平均是一个音功率的 9 %，最外一个音 4.4 倍，整包不变。迫零后各音同权，估计偏小的音就把又大又错的 LLR 交给解码器，每个符号、每个码字都错在同一处。
- 迫零后第 k 个音的噪声是 σ²/|H_k|²，权本来就该是 |H_k|²；估计准、信道 flat 时各音的权相同，什么也不改，所以原来没露出来。这不是调参数，是解映射写得不对；多径下它本来也是必须的。
- 写下的预期是加权后交叉点到 −0.25 … −0.1 dB，实测 +0.05 dB：估计的噪声剩 0.54 dB，是它一阶代价的全部 0.48 dB，不是我按“PSK 只吃相位那一半”估的 0.25 dB。0 dB 附近估计的误差是一个音功率的 12 %，权也跟着带噪，分不出一个不伤人的幅度那一半。没有再往下追。

### 9g. 标准的 L-CEF，做成能单独拷走的模块（2026-11-25，feat/ay-preamble；mmw60_trx#89，jcas60 发来）

jcas60（60 GHz 通感一体）要拿 802.11ay 单载波的 Golay 训练场做感知，想 vendor 本库的 `ay/golay.py` 与 `ay/training.py`。它动手前查了依赖并报回，我逐条核过，都属实：
`golay.py` 只依赖 numpy；`training.py` 拷不出去（`from .. import spec` 会带进本库的本地表和第二份 spec_sources，还依赖 `ofdm.py`，后者函数内引 `rx.tracking`）；
而且 `training.py` 建的是 **EDMG OFDM 包的** EDMG-STF / EDMG-CEF——单载波单流没有这两个场（`edmg.sc_siso_preamble` 两项都是 0），它的 Golay 训练场是 legacy 部分的 L-STF / L-CEF，本库没按标准拼过。

**建了什么**：`ay/preamble.py`，只 import numpy 与 `golay`，**不读规范表**——规范的数（生成 Ga / Gb 的 D_k / W_k、Gu512 / Gv512 的拼法、发送顺序）全是参数；本库自己的调用层是 `edmg.l_cef` / `l_cef_prefix` / `golay_pair_128`（读 `dmg.golay_sequences` 与 `dmg.cef_golay_layout`）。
“读条目”与“建波形”分两层，是因为两个库 pin 的 spec_sources 不是同一个提交（本库 `65ff5e4`，jcas60 `f9ce3f2`）：波形模块不该替调用方决定读哪一份。

**算出来的**（`tests/test_ay_preamble.py`，都是算的，不是引的）：

- 递推出来的 A_7 / B_7 **倒着读**才是规范列的 Ga128 / Gb128（64、32 两个长度同样）；本库原有的 `golay_pair` 不倒，所以以前的 SC 训练与规范的序列不是一回事（`assumed.ay_preamble` 一直是这么声明的）。
- 场长 1152 码片（SC：Gu512、Gv512、Gv128；OFDM：Gv512、Gu512、Gu128），与条目的 `cef_chips`、`edmg.sc_siso_preamble` 的 `l_cef_chips` 一致；末尾 128 码片两种排法都是 −Gb128（条目里的那句话）。
- **Gu512 与 Gv512 单独拿出来不是互补对**（非周期自相关之和在非零滞后上不为零）。让它成为信道估计场的是两头各 128 码片：场尾是第二段的头 128（循环后缀），场**前面**要站着第一段的尾 128（循环前缀；两种排法算出来都是 −Ga128）。
  带上它，两段相关之和在滞后 0 是 1、在 ±128 码片内其余 256 个滞后上**恰好是 0**，区外不为零；去掉前缀，负滞后一侧就不干净了。±128 码片在 1.76 GHz 上是 ±72.7 ns。
- 过一条 4 径信道（时延 0 / 7 / 101 / 128 码片），相关读出来的就是各径的复增益（1e-12 内）；时延 140 码片的径读不干净。
- π/2 旋转按查表做（1, j, −1, −j），没有 `exp` 的 1e-16 余数。相关用**带旋转的参考**：先把旋转从接收信号上去掉再相关的话，每径会多带“每码片时延四分之一圈”的相位（第一版就是这么写的，信道那条测试抓到）。

**“能单独拷”是测出来的**：语法树核对两个文件的 import（函数内的也算）；另把两个文件拷进一个别名的包、在一个 import 不了 mmw60 的解释器里建场，与 `edmg.l_cef` 逐位相同。六种变异（模块里加 `spec` 引用、函数内藏一个引用、不倒序、旋转反向、前缀取错头、拼接时丢符号）各自变红，还原变绿。

**没做的**：本库仍不发 legacy 部分——这个模块没有接进任何链路，数字不动（指纹 122 个值逐位相同）。L-STF 与 TRN 子字段的组成不在本库读的规范表里（只有码片数：L-STF 2176），所以前面那 128 码片在这里是“第一段的循环前缀”，
至于规范的 STF 是不是以它收尾，本库没有出处可核。`training.py` 的拆分（jcas60 的第 2 项，它的 OFDM 感知排在后面）记在 ROADMAP。
