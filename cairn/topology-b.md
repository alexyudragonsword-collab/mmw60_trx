# 拓扑 B：60 GHz 零中频前端

## 1. 前端怎么建（里程碑 1-B 的决定）

拓扑 B 的 60 GHz 收发机就是 wifitrx 的 `TxChain` / `RxChain` 跑在 `fs_eff = fs_base × K`（`frontend.model: zero_if_chain`）：
这既是"WiFi 7 芯片的零中频架构时钟 ×K"的字面含义，又让 wifitrx 的 14 步校准序列原样真跑（铁律 4）。
随 K 变的量全部在 `frontend/Frontend60` 里派生：转换器位数 = round(ENOB(fs_eff))，ENOB 每倍采样率降 0.5 bit（`assumed.converter_bits_per_octave`）；
LPF 角频 = wifitrx `recommended_lpf_corner_hz(BW × K)`；IQ 失配按绝对 ps / ns（同一器件在更宽的带上更差）；LO 泄漏 −30 dBc、RX 自混频 DC −25 dBc；
PA = Rapp 的 dBm 版 `ScaledRappPA`，取一颗测量的 60 GHz CMOS PA（`pa60.asada_eumc2011`，Asada EuMC 2011：Psat 14.6 dBm、增益 23.2 dB、P1dB 10.0 dBm、峰值 PAE 16.3 %；Rapp p = 1.286，P1dB 在 Psat 下 4.6 dB，`assumed.pa60_surveyed_pick`）；AM/PM 仍是 11ad EM 的（原文没给）。
工作点由模拟 VGA 调到 Psat − OBO，数字驱动固定 −16.5 dBFS（DAC 不削顶）。
OBO 是 7.5 dB（Pout 7.1 dBm，P1dB 之下 2.9 dB）：PA 单独在 OFDM 式包络上刚到 −21 dB EVM 的回退（`assumed.pa60_operating_rule`）。−21 dB 是 802.11ad 16-QAM 的 TX EVM 限，也是 60 GHz 发射机 `pa60.wu_isscc2015` 标称输出的口径；值是 `derived.pa60_obo_at_evm_limit_db` = 7.5（算出来 7.457，示例 09）。
（2026-11-13 之前沿用 Liu 的 8 dB：Pout 6.6 dBm，P1dB 之下 3.4 dB。灵敏度档 `config.tgad_em_pa(cfg)` 仍带 Liu 的 8 dB。）
（2026-11-12 预设换成测量的 PA 之前是 11ad EM 的 Rapp：p = 0.81、P1dB 在 Psat 下 9.5 dB，Psat 15 dBm、增益 20 dB、峰值 PAE 20 %，都是 `assumed`，Pout 7.0 dBm。它现在是灵敏度档 `config.tgad_em_pa(cfg)`。Liu 自己的预设（示例 00 / 01）没换。）
`Frontend60` 是两拓扑共用的实例（`LinkSim(cfg, frontend=fe)`，`tests/test_frontend.py::test_law2_*`）；拓扑 A 拿同一个对象做 60 GHz 级（`topology-a.md`）。

锚：前端全关时 K = 1 与 K = 8 的链路 EVM 相同（−39.9 dB，差 < 0.1 dB）——链路里剩下的是 LPF 群时延与信道估计平滑的偏差，K 只改时间尺度。
里程碑 0 的 behavioural 路径逐位不变（指纹 68 个值相同）。

## 2. 网格：基准带宽 × K（示例 02，`examples/expected/02_upclock_grid.txt`）

口径：解析底板 = 相噪 ICI（wifitrx `cpe_partition`，T_FFT/K，TX+RX）⊕ IQ 镜像（`irr_db` 在占用带上平均，TX+RX，未校准）⊕ 转换器（DAC+ADC，ENOB(fs_eff)，带内份额）⊕ PA（测量的 PA 在 OBO 7.5 dB 的隔离 EVM −21.1 dB；2026-11-13 之前 OBO 8 dB 上 −22.1 dB；2026-11-12 之前 11ad EM 的 Rapp 是 −18.1 dB）⊕ GI 外 ISI；
"能" = CFO 捕获 + 频率规划通过 + MCS0 的 TX EVM 要求（wifitrx `tx_evm_limit_db`）留 3 dB；"IQcal" 列把 IQ 换成校准后每侧 45 dB 残余（`assumed.irr_after_cal_db`）；"no-PA" 列去掉 PA 项（回退是设计者按 MCS 调的旋钮，其余不是）。
时域列 = 同一格在 wifitrx 链上、flat 信道、无噪声的 EVM（全开 + 逐项隔离）。

- 表里的“结论”是发射机合规口径。解码器口径（示例 02 的 dec / dec-cal 列，`comparison-table.md` §2b）高 1–3 档：≤ 0.32 GHz 的 11be 格 MCS5、0.64 GHz 的 11be 格 MCS4、11ac 20 MHz 格 MCS3–4；1.28 GHz 的 11be 格 MCS3（合规 MCS0）；2.56 GHz 的 11be 格 MCS0（合规“不能”）；5.12 GHz 及以上仍不能；校准后 11be 格 MCS5–6（×32 的五格 MCS5，其余 MCS6）。
  （2026-11-13 回退改成 7.5 dB 之前：≤ 0.32 GHz 的 11be 格 MCS5–6（≤ 0.16 GHz 的三格 MCS6）；校准后只有 5.12 / 10.24 GHz 的两个 ×32 格是 MCS5。）
  （2026-11-12 预设换成测量的 PA 之前：≤ 0.64 GHz 的 11be 格 MCS4、11ac 20 MHz 格 MCS3，校准后 11be 全部 MCS4；1.28 / 2.56 GHz 两档不变。）C1–C3 之前（逐符号 CPE、固定 3 音平滑的接收机）0.64 GHz 是 MCS3、1.28 GHz 是 MCS2–3。
- 解析与时域在 ≤ 1.28 GHz 内差 −0.9 … +0.8 dB（2026-11-13 回退改成 7.5 dB 之前 −0.8 … +0.8；换 PA 之前 −1.1 … +0.5）；更宽时 IQ 镜像接近信号功率，线性叠加失效（时域更差，2.56 GHz 差 0.3–1.3 dB，回退改之前 0.3–1.2），解码器上限取两者中较差的一个（`decoder_floor_db`）。时域列是接收机看到的 EVM，所以跟着接收机走：C1–C3 的自动平滑跨度把 ≤ 2.56 GHz 的格的时域读数压低了 0.1–1.2 dB（信道估计里的失真被多平均了几个音），解析列与结论列一格没动。A2 之后 11be 格的时域列来自编码的 MCS0 数据域（不再是随机 16-QAM 载荷），并且前导多了 DC 测量用的静默段。
- **用户预期的"80 MHz × 32 或 160 MHz × 16 + CFO 估计"**：CFO 捕获在 60.48 GHz 上 K ≥ 4 都成立（2.42 MHz < ±2.5 MHz），它们的瓶颈不是 CFO 而是 2.56 GHz 上未校准的频率相关 IQ 不平衡（150 ps 群时延失配在 ±1.28 GHz 边缘是 1.2 rad）；校准后（示例 03 实测 2.56 GHz 上 irr_min 40.2 / 45.9 dB）网格（45 dB）回到 PA 限的 MCS3，同台表用实测 IRR 是 MCS2（§3 IRR 一条）。
  （2026-11-13 之前校准跑在默认驱动上，实测 38.5 / 46.2 dB，两处都是 MCS3；换 PA 之前 38–42 dB、MCS2。）
- 相噪项随 K 变好（T_FFT 变短，CPE 份额变大）：11ac 20 MHz 基准 −26.7（K=4）→ −31.6 dB（K=32）；11be 同带宽下比 11ac 差 1–2 dB（T_FFT 长 4 倍）。
- GI 外 ISI：7 ns 散射尾在 K=32 的 25 ns GI 外是 −25.9 dB，开始与 IQ 同量级。
- 转换器：按 −0.5 bit/octave，20 GS/s 处 7.8 bit → −34 dB，不是任何格的瓶颈；按 −1 bit/octave（Walden）11be 160×32 处 6.6 bit → −29.9 dB，仍非瓶颈。
- DPD 代价（dsp_ip dpd_poly P=4 DDR r=1 140 项，Horowitz 45 nm 运算能耗）：11ac 20×8 MCS3 208 Mb/s → 355 pJ/bit；11be 20×32 MCS2 826 Mb/s → 358 pJ/bit（换 PA 之前 MCS2 156 Mb/s → 474、MCS1 551 Mb/s → 537 pJ/bit）；2.56 GHz 带宽需 3.8 个 P=4 数据通路（2727 MSPS 各）。这是记账不是测量。
  掉到 MCS2 的四个 0.32 GHz 格每比特贵了 1.3 倍左右：11be 80×4 MCS2 432 Mb/s → 342 pJ/bit，11be 20×16 与 40×8 MCS2 413 Mb/s → 358，11ac 80×4 MCS2 351 Mb/s → 421（2026-11-13 回退改成 7.5 dB 之前都是 MCS3：576 → 256、551 → 269、468 Mb/s → 316 pJ/bit）。

## 3. 校准：wifitrx 序列在每个 K 上（示例 03，`examples/expected/03_calibration_at_k.txt`）

链路 = 同一个 `Frontend60`，poweron 剖面，wifitrx@7b8d08e；K = 1/4/8/16（20/80/160/320 MHz，wifitrx 有标准导频的评分波形）、K = 32（640 MHz）与 11be 80 MHz × 32（2.56 GHz）。
2026-11-13 起每一列的最终 EVM 检查都落在预设的 PA 工作点上（从 Psat 回退 7.5 dB，`derived.pa60_obo_at_evm_limit_db`；`run_cal_at(obo_db=…)` 调 VGA 并重跑整套序列直到落点差 ≤ 0.1 dB）：六列落在 7.43–7.51 dB，2.56 GHz 列要跑两遍，其余一遍。
后两列没有标准导频表，用**基准波形 × K**（`calcheck.upclocked_scoring_config`：基准带宽的音与导频原样，音距 × K；wifitrx 96078aa 起 `TonePlan` 自带导频，wifi_trx_cal#4），整套序列的激励与评分都是它。每次采集 8 个符号（`assumed.cal_capture_symbols`）。

| 步骤 | K=1 | K=4 | K=8 | K=16 | K=32 (640M) | 80M×32 (2.56G) | 机理 |
|---|---|---|---|---|---|---|---|
| tx_lpf_corner / rx_lpf_corner | ok / ok | ok / ok | ok / ok | ok / ok | ok / ok | ok / **退化 8.7 %** | 角频随 BW 缩放；2^14 样本的扫频分辨率随 fs 变粗 |

| tx_lo_leak_loopback（dBc） | −68.8 | −72.6 | −68.9 | **−55.3** | **−56.8** | **−39.8** | RX LO 偏置固定 4.8 MHz：K ≥ 8 时泄漏箱落进信号带内 |
| loopback_delay（ns） | 71.8 | 23.3 | 14.7 | 10.5 | 8.2 | 6.8 | 6 ns 回环 + LPF 群时延；max_lag 32 样本在 ≥ 5.3 GS/s 越界（2.56 GHz 处 5.12 GS/s 刚好未越） |
| tx_iq（irr_min dB） | 58.4 | 57.7 | 53.4 | 55.3 | 48.1 | **40.2** | 绝对 ps 失配在宽带上相位误差 ∝ K，校正 FIR 抽头数不变 |
| rx_iq（irr_min dB） | 57.3 | 55.9 | 54.1 | 51.9 | 49.2 | **45.9** | 同上 |
| group_delay（误差 ps） | −1.4 | −28.4 | −40.1 | −16.6 | −7.7 | 9.0 | 容差 80 ps 内 |

| agc_sweep（落点误差 dB） | 0.3 | 0.1 | 0.3 | 0.0 | 0.1 | 0.1 | 探针 23 MHz 固定，未受影响 |
| final_loopback_evm（tx_evm_modem dB） | −21.8 | −21.6 | −21.4 | −21.8 | −21.9 | −23.9 | 标准带宽用标准波形，更宽的用基准波形 × K |

**DPD 与最终 EVM 两行读的是工作点。** 预设的工作点是 PA 单独在 OFDM 包络上刚好 −21 dB 的回退（`assumed.pa60_operating_rule`，ROADMAP C10 已定），所以最终的仅发 EVM 一行在 −21.4 … −21.9 dB（2.56 GHz −23.9），贴着那条线、略好一点：DPD 步留下的是观测通路上最好的一轮。
（2026-11-13 之前示例 03 跑在 wifitrx 的默认驱动上，不在预设回退上（原 ROADMAP C8 最后一条，已做，见 `cairn/LOG.md` 2026-11-13）。测量的 PA 增益 23.2 dB，那个驱动落在离 Psat 6.92 dB（Pout 7.68 dBm，P1dB 之下 2.3 dB）；那时 dpd 一行 −20.8 / −20.8 / −20.8 / −21.4 / −21.2 / −20.4，最终 −20.5 / −20.6 / −20.4 / −20.5 / −20.8 / −20.7 dB；IRR 57.0 / 58.4 / 52.9 / 53.3 / 47.7 / 38.5（tx）、56.3 / 56.8 / 53.1 / 50.9 / 47.6 / 46.2（rx）。
示例 03 现在留一行默认驱动的灵敏度（K = 8）：落在 6.92 dB，回环 / 仅发 −21.0 / −20.4 dB，与那时的表逐位相同；同一 K 在预设工作点上 −22.1 / −21.4 dB。）
（2026-11-12 预设换成测量的 PA 之前，旧 PA 增益 20 dB，默认驱动落在离 Psat 10.73 dB：dpd −27.3 / −25.0 / −26.5 / −26.4 / −23.1 / −25.2，最终 −25.5 / −25.1 / −26.7 / −26.1 / −22.8 / −26.0 dB；IRR 55.3 / 55.8 / 50.4 / 51.1 / 46.9 / 37.9（tx）、56.3 / 55.2 / 50.6 / 52.3 / 46.5 / 42.1（rx）。那一组数比现在好，是因为工作点离 Psat 远 3.2 dB，不是旧 PA 更线性：同在离 Psat 8 dB 上，测量的 PA 好 3.4 dB，示例 09 §4。）
IQ / LO 泄漏 / 群时延几行也跟着工作点动（换到预设工作点：IRR −1.1 … +2.0 dB，最大的是 320 MHz 的 tx_iq 53.3 → 55.3 dB 与 2.56 GHz 的 tx_iq 38.5 → 40.2 dB），各行的机理判断不变。

最后一步的三个视图（wifitrx 的 modem 口径，标准接收机读到的；回环 / 仅发 / 仅收，dB）：K = 1 −21.7 / −21.8 / −27.4；K = 16 −22.8 / −21.8 / −27.8；640 MHz −21.0 / −21.9 / −29.8；2.56 GHz −23.4 / −23.9 / −28.8。
仅收一列不随工作点动（默认驱动时 −27.3 / −27.8 / −29.8 / −28.8，换 PA 之前 −27.4 / −27.9 / −29.6 / −28.3）；回环与仅发跟着 PA 的工作点走（默认驱动时 K = 1 −20.6 / −20.5，K = 16 −21.3 / −20.5，640 MHz −20.1 / −20.8，2.56 GHz −20.5 / −20.7；换 PA 之前 −26.4 / −25.5、−29.3 / −26.1、−21.6 / −22.8、−24.3 / −26.0）。
2.56 GHz 列的 genie 口径回环 EVM 校准前后是 22.0 / −13.5 dB，modem 口径 −23.4 dB：差的那部分是标准接收机的信道估计与导频跟踪能吸收的线性项（默认驱动时 23.6 / −14.6、−20.5 dB；换 PA 之前 2.2 / −12.9、−24.3 dB）。

- 没有一步在 2.56 GHz 上抛异常；"失效"表现为退化：LO 泄漏环检从 −69 到 −40 dBc（4.8 MHz 固定偏置在 2.5 MHz 音距下落在第 2 个子载波上，泄漏箱被数据淹没），IQ 校准从 56–58 到 40.2 / 45.9 dB，RX 角频偏 8.7 %。最终 EVM −23.9 dB，比 320 MHz 的 −21.8 好 2.1 dB：这一列的 DPD 拿回的多（默认驱动时 −20.7 对 −20.5、换 PA 之前 −26.0 对 −26.1，都持平）。
- **采集长度仍然决定 640 MHz 列的 DPD**：11ac 20 MHz 基准 × 32 只有 52 个音、64 点 FFT，8 个符号是 1280 个样本，GMP 拟合不够：DPD 步每一轮在观测通路上都比不加预失真差，所以一轮都没写入，
  仅发 EVM −21.9 dB，与不开 DPD 的 −21.9 dB 相同；采 32 个符号（5120 样本）是 −27.7 dB（8 个符号时 DPD 步自己的读数 −22.1）。示例 03 有 32 符号的灵敏度行；默认值没有改（每列同一个符号数，`assumed.cal_capture_symbols`）。
  在预设工作点上这一列不比别的列差（各列最终 EVM −21.4 … −21.9 dB，2.56 GHz −23.9）；但 32 个符号比 8 个好 5.8 dB，采集长度这一条成立。（默认驱动时 −20.8 对 −24.1 dB，差 3.3 dB。）
  （2026-11-12 预设换成测量的 PA 之前，这一列 −22.8 dB 比其余列差 2.3–3.9 dB，32 个符号是 −29.0 dB；K = 1 的同一个 64 点波形 8 个符号够用（−25.5 dB）。现在 K = 1 的 DPD 步在工作点上拿回 2.4 dB（−21.8 → −24.2，DPD 步自己的读数），K = 32 一轮都没写入：同一个 64 点波形、同样 8 个符号，差别仍在 K。）
  K = 32 上为什么不够没有单独验证（候选：观测 ADC 的 ENOB 随 fs 下降，辨识噪声更大）。

## 3b. PA 的电记忆与 DPD 抽头间隔（示例 07，`src/mmw60/pamemory.py`）

预设的 60 GHz PA 是无记忆的 Rapp。时钟 ×K 之后多出一个标准速率链路碰不到的问题：PA 的记忆跟不跟着时钟走？两端：

- **随信号缩放**：抽头永远隔一个样本（PA 是为它承载的带宽设计的）。预失真器在每个 K 上面对同一个问题。
- **按秒固定**：抽头隔 1 / fir_fs 秒，在 fs_eff 上隔 fs_eff / fir_fs 个样本，逐样本的 GMP 基函数够不着。

模型是 wifitrx 的 `ReferencePA`（PA_DPD 的参考 PA：3 抽头输入 FIR → Saleh → 2 抽头输出 FIR，`fs` / `fir_fs` 来自 PA_DPD@02ca433），按本库前端的增益 / Psat 定标（2026-11-12 起 23.2 dB / 14.6 dBm，之前 20 dB / 15 dBm；参考 PA 的 EVM 读数因此动了 0–1.9 dB，大的在 K = 32 的崖上，其余 ≤ 0.7 dB）；预失真器是 wifitrx 自己的 DPD 步，GMP 的抽头间隔从 wifi_trx_cal@da37888 起可传（`run_cal_at(dpd_tap_spacing=…)`）。
PA 模型与 `fir_fs` = 80 MS/s（12.5 ns 一个抽头）都是假设（`assumed.pa_memory_model` / `assumed.pa_memory_fir_fs_hz`）：这是只在一种方案上做的灵敏度研究，预设与同台表不变。11be 80 MHz 基准，2 倍过采样，每一行的最终 EVM 都落在表里写的输出回退上（自 Psat）。

**读法：代价按回退读，不按某一个回退上的 EVM 读。** DPD 的收益在 PA 接近饱和时断崖式消失，两种记忆规律的崖相距 1–2 dB，预设回退正好在崖区：K = 8、7.5 dB 上随信号缩放的那颗刚跳下崖（−26.3 dB），按秒固定的那颗 DPD 一点没拿回（最好 −20.5，与不开 DPD 相同）。

## 4. 被推翻的判断

1. 以为校准序列会在 K ≠ 1 上直接失败（里程碑 0 读码的结论："run_full_cal 第一步就 ValueError"）——那是把 SCS 配成 312.5 kHz × K 的后果；用标准带宽的评分波形（160 MHz 11ac、320 MHz 11be）配链路跑在 fs_eff，序列全程能跑到 320 MHz。
2. 以为 K = 4 在拓扑 B 上一定失锁——那是 73.44 GHz 的数；60.48 GHz 上 40 ppm = 2.42 MHz，L-STF ±2.5 MHz 刚好接住，门槛通式 K > 2·Δf_max / 1.25 MHz = 3.9。
3. 以为 wifitrx 的 `align_delay` 能给链路定时——复波形互相关在 2.94 MHz CFO 下 1 µs 内去相关，整包定时错；改用包络互相关（`sim/link.py::envelope_lag`）。
4. 以为 wifitrx `ScaledPA` 能包 Rapp——它用 AM/AM 的 argmax 找饱和点、在 r_sat/100 读小信号增益，对单调的 Rapp 两个锚都错；自写 `ScaledRappPA` 按 Asat² 与 g 解析锚定。
5. 以为把 DPD 的抽头间隔设成 fs_eff / fir_fs 就接得住按秒固定的记忆（给 PA_DPD#4 / wifi_trx_cal#5 提需求时的出发点；PA_DPD 单拟合 PA 时 `tap_spacing` 1 → 4 是 −29.2 → −41.0 dB）——放进链路，预设回退上匹配间隔在 K = 8 / 32 都不如逐样本，K = 4 上全部比不开 DPD 差；只有回退 ≥ 10.5 dB 的 K = 32 上它才赢（§3b）。
6. PA 记忆研究的第一轮读数（不对齐回退、两种规律各自过 `ScaledPA` 定标）是“代价 2.3 / 2.3 / 1.1 dB，K = 32 上匹配间隔好 4.4 dB”——比的是两个工作点：按秒固定的那颗小信号增益被定高了 1.80 dB、回退少 0.7 dB。统一定标并把每一行放到回退 8 dB 上之后是 7.3 / 6.0 / 3.2 dB，匹配间隔在这个回退上反而差。测试里一条增益断言先红了才查出来。
7. 以为“记忆按秒固定时预设回退上 DPD 基本失效，匹配的抽头间隔只在退到 10.5 dB 的 K = 32 上才赢，迭代次数不是原因”（§3b 的第一版，da37888）——K = 32 上那正是迭代造成的：上游改成留观测最好的一轮（0.7.39）之后，匹配间隔在预设回退上是 −25.2 dB，离随信号缩放的 −25.8 只差 0.6 dB。
   真正决定代价的是抽头隔多少个样本（8–16 个最糟）。教训：在一个 K 上排除的原因，不能替别的 K 排除。
8. 以为“代价由 PA 的抽头隔多少个样本决定，隔 8–16 个样本最糟，差 4–6 dB”（§3b 的第二版，7b8d08e）——那是在预设回退 8 dB 这一个点上读的 EVM 差，而这个点正好在 DPD 的崖上：随信号缩放的那颗 PA 的崖在 7.0–7.5 dB，按秒固定的晚 1–2 dB。
   细扫回退、在同一个 EVM 上比各自要退多少，代价是 0.5–2.3 dB。对方复现不出来（他们在远离崖的地方量）正是线索。教训：比较两个非线性系统时先看指标随工作点的曲线，再决定在哪个点上比；单点上的大差距先怀疑是斜率。
9. 以为示例 03 / 08 的校准表不在预设回退上，只会让 DPD / 最终 EVM 两行偏乐观（wifitrx 默认驱动落在离 Psat 10.4–10.7 dB，比预设多退 2.5 dB，ROADMAP C8）。
   2026-11-12 预设换成测量的 PA（增益多 3.2 dB）后，同一个驱动落在离 Psat 6.92 dB，反过来偏悲观：K = 8 的回环 / 仅发 / 仅收从 −29.0 / −26.7 / −27.5 变成 −21.0 / −20.4 / −27.5 dB，看起来像 PA 变差了。
   放在同一回退（8 dB）上比，新 PA 反而好（示例 09 §4：仅发不开 / 开 DPD −22.2 / −24.2 对 −18.8 / −19.6 dB）。教训：默认驱动定的是输入电平，换了增益的 PA 落点就变；校准读数先问它在哪个工作点上读的（§3）。
   2026-11-13 起示例 03 / 08 都在预设工作点上校准（`run_cal_at(obo_db=fe.obo_db)`，ROADMAP C8），这一条的起因消掉了。

## 5. 前端的三个面：接收前端、收发隔离、发 / 收天线增益（示例 08，`src/mmw60/frontend/rxfront.py`）

起因是 fmcw_radar 的消费清单（mmw60_trx#14）：雷达要从 `Frontend60` 读接收增益 / NF / 压缩点、收发隔离、两副天线的增益，而这三样此前要么藏在 wifitrx 的表里，要么没有。它们现在是同一个 `Frontend60` 实例上的三个面，不为雷达另开接口：

| 面 | 怎么读 | 预设 | `config.surveyed_frontend` |

| 接收前端（最高增益档） | `fe.rx_front.gain_db / nf_db / iip3_dbm / p1db_inband_dbm / p1db_oob_dbm`，`fe.rx_front.sourced` | wifitrx 的 WiFi 7 梯子：37 dB / 3.5 dB / −20 dBm / −29.6 dBm，`sourced = False` | 梯子整体平移到增益 27 dB、NF 6.1 dB、IIP3 −20 dBm |

**出处**：按用户的要求以通信文献为主。基准档的接收机和天线取同一颗 60 GHz 通信收发机（`rx60.comm_asada2011`，A-SSCC 2011，65 nm），**读过原文**：变频增益高 / 低档 27 / 17 dB，“整机 NF 小于 6.1 dB，IIP3 实测 −20 dBm”，封装内天线 2 dBi。隔离取一篇摘要（`isolation.tx_rx_tue2018`，读过摘要原文）里“加隔离结构后 40 dB、比不加好 15–20 dB”减出来的下端 20 dB。雷达芯片（`rx60.radar_iwr6843` 与 `rx60.radar_iwr6843_fig7_2`，读过数据手册）只作对照。另有三条只读到搜索摘要，标着未核实，都只作灵敏度档（`spec-sources.md`）。哪一档取哪个数是 `assumed.frontend_faces_pick`。

- **校准的回环 / TX 单独读数现在被 PA 的工作点压住，几乎不随 NF 动**：wifitrx 的序列经接收机观测，NF 从 3.5 到 6.1 dB，最终回环 EVM 差 0.1 dB；到 12 dB 差 0.8 dB，TX 单独的读数差 0.0 dB。
  原因与示例 03 相同（§3）：最终检查落在预设的 PA 工作点上（离 Psat 7.5 dB，Pout 7.1 dBm，P1dB 之下 2.9 dB），五档的 TX 单独都是 −21.4 dB，由 PA 压缩定，观测噪声的份额被它盖住（推断，没有单独量）。这些数比换 PA 之前差，是工作点挪了，不是 PA 差了：同一回退上新 PA 更好（示例 09 §4）。
  （2026-11-13 之前校准跑在 wifitrx 的默认驱动上：换成测量的 PA 后落在离 Psat 6.92 dB（Pout 7.68 dBm，P1dB 之下 2.3 dB），五档的 TX 单独都是 −20.4 dB，到 12 dB 回环差 0.6 dB。现在离压缩远 0.6 dB，这个差多了 0.2 dB，图景不变。）
  （2026-11-12 预设换成测量的 PA 之前，同一驱动落在离 Psat 10.73 dB（Pout 4.27 dBm），校准表会随 NF 动：最终回环 EVM 差 1.1 dB，到 12 dB 差 5.5 dB，TX 单独也差 1.6 dB，观测噪声进了估计。新 PA 在离压缩更远的工作点上会不会重新出现，没有量。）
- “校准读到的 RX NF”是回环电平落到的那一档的等效 NF，不是最高增益档的。换档电平随 NF 移动（下一小节），这一列要连着档位读。现在五档随 NF 单调：11.1 / 13.4 / 14.3 / 17.1 / 19.0 dB（2026-11-13 之前 11.2 / 13.5 / 14.4 / 17.1 / 19.0）。
  （换 PA 之前回环电平正好在第 1、2 档的换档点附近，基准档那一行落在第 1 档、读数 9.6 dB 比预设的 10.8 dB 还低。）

### 梯子怎么平移（`assumed.rx60_ladder_shape`）

每档的 NF、IIP3、增益各加同一个 dB 数，增益步进不变。换档电平按 wifitrx 自己的规则走：`chain/agc.py` 把每个换档点定在噪声对 IM3 的平衡点 t_i = (2·IIP3_i + NF_{i+1} + 常数) / 3，所以整体平移时每个电平移 (2·ΔIIP3 + ΔNF) / 3，与增益无关。以官方表的电平为基准，什么都不给时就是 wifitrx 的梯子。`tests/test_frontend_faces.py` 拿 wifitrx 的 `rebalance_thresholds` 对着核。

增益取 27 dB 后，灵敏度电平上基带 VGA 顶在 40 dB 的上限，ADC 输入比目标低约 7.5 dB；SNR 2 / 10 / 30 dB 上的链路 EVM 与增益 37 dB 时相同。

### 泄漏预算：压缩点是两个量（PA 输出 7.1 dBm；2026-11-13 之前 6.6 dBm，2026-11-12 之前 7 dBm）

接收机有两个输入压缩点，泄漏碰到哪一个看用法（fmcw_radar 在 mmw60_trx#14 上指出，TI 手册把两者分开给）：

- **带内的**（`fe.rx_front.p1db_inband_dbm`，各档见 `p1db_inband_by_gain()`）：有用信号碰到的，也是全双工链路的泄漏碰到的（泄漏就在载频上）。由 IIP3 减 9.6 dB 得到（`assumed.rx60_p1db_from_iip3_db`；链路里的三次项正好在 IIP3 − 9.64 dB 压缩 1 dB，测试守着）。
- **带外的**（`fe.rx_front.p1db_oob_dbm`）：基带高通之前那几级的压缩点，用低于高通截止的单音量。FMCW 雷达的发射泄漏拍下来落在高通以下，碰到的是它。链路不消费这个字段；没有出处就是 None，`leakage_budget()` 里对应的余量也是 None，**不拿带内的数顶替**。

### 被推翻的判断（本节）

1. 第一版的换档电平是自己拍的规则（随 IIP3 平移、随增益反向平移）。读 wifitrx 的 `chain/agc.py` 才看到它有自己的平衡点规则，而且注明“任何 NF / IIP3 的改动之后用它”。改成跟它走；增益不再进换档电平。
2. 第一版把 −33 dBm 标成“ITU-R M.2003”。读原文发现那是 2012 年版，现行版已经改成功率密度。
3. 第一版基准档的天线取 6 dBi（另一篇论文的搜索摘要）。读到 Asada 原文后，它自己的封装内天线是 2 dBi；基准档改成同一篇原文的数，6 dBi 留作未核实的灵敏度档。
4. 第一版说“增益没有出处”。原文同一段就给了变频增益 27 / 17 dB，搜索摘要没带出来。
5. 合并进 main 的第一版（PR #15）在泄漏表里拿泄漏去比通信前端的压缩点（带内的，从 IIP3 折出来），旁边雷达芯片那一列用的却是带外的 −12 dBm，并据此写了“雷达芯片的带外压缩点高 17.6 dB，这是两类前端的差别”。这句不成立：17.6 dB 主要是两种量法的差。同一种量法（带内）下两者只差 5.6 dB。fmcw_radar 在 mmw60_trx#14 上指出压缩点是两个量之后改成两个面。教训：两个数并排比之前，先确认它们量的是同一个东西。
6. 天线表里的 2 / 3.5 / 5 dBi（“Infineon AN600”）三行已删。提供这组数的 fmcw_radar 读了 AN600 原文后撤回：那份应用笔记里没有天线增益。本库当时标了未核实、只作灵敏度档，结论不受影响。
7. 以为“Asada 2011 的发射机 Psat 6.5 dBm，比本库假设的 PA（15 dBm）小很多”（“没有接上的地方”最后一条的第一版）。6.5 dBm 是收发机的发射输出，没有 PA 级；同组独立 PA 是 14.6 dBm，15 dBm 在测量范围里，偏的是形状（P1dB 在 Psat 下 9.5 dB，测量的 4.6 dB）。2026-11-12 预设换成了这颗测量的 PA（示例 09，`cairn/LOG.md` 2026-11-12）。又一次把两个不同的量并排比。
