# 同台表（示例 04，`tools/budget_report.py`）

## 1. 表是什么

`mmw60.compare.scheme_matrix` 把 `TOPOLOGIES × WAVEFORMS` 的 8 个格子全部点名：建好的格子有配置和数字
（拓扑 B × `be`：K = 1 的 WiFi 7 链；拓扑 B × `be_upclocked`：K = 1 / 4 / 8 / 16 / 32），没建的写明哪个里程碑带来它
（拓扑 A × `be`：里程碑 1 / A1，另一会话；拓扑 B × `ay_ofdm` / `ay_sc`：里程碑 3），不成立的组合写 n/a
（A 不改波形；ay 是 B 的硬件）。`tests/test_compare.py::test_law2_matrix_names_every_topology_x_waveform_pair` 守着矩阵完整。

**一个 `Frontend60` 实例给每一行**（铁律 2 的完整测试 `test_law2_every_scheme_on_the_shared_frontend_reads_the_k1_evm_when_ideal`：
理想前端实例共用，ppm = 0 / 理想 LO / 理想 PA 下每种已建方案的 EVM 与 K = 1 差 < 0.1 dB；A 与 ay 的行以它们的里程碑为由 skip）。
LO 链是该实例的一部分：6 GHz 的 K = 1 行也跑在共用的 60 GHz 剖面上（它自己的 `wifitrx_wifi7` 设置只在"单独仿真"时生效——§4）。
这是有意的：表比较的是"同一套硬件、时钟 ×K"，不是"两颗不同的芯片"。

每行的列（`compare.Row`）：数字学（BW_eff、SCS、T_sym）、CFO（Hz、子载波数、L-STF 是否接住）、解析底板及其分项、
同格的时域 EVM（flat、无噪声）、wifitrx `EvmBudget` 喂同样分项的预测、MCS 上限（未校准 / 校准后——用示例 03 **实测**的 IRR，
`derived.irr_after_cal_measured_db`，按不大于该行带宽的最近一档）、上限处的速率与 b/s/Hz、PA 工作点对共用 EIRP 上限的余量、
功率分块 pJ/bit（§5）。

IQcal 列的实测 IRR 自 2026-11-13 起来自在预设工作点上跑的校准（示例 03 / 08 用 `run_cal_at(obo_db=fe.obo_db)`）。
之前用 wifitrx 的默认驱动，在测量的 PA 上落在 Psat 下 6.92 dB，不是谁选的工作点。
20 / 80 / 160 / 320 / 640 / 2560 MHz 各档现在是 57.3 / 55.9 / 53.4 / 51.9 / 48.1 / 40.2 dB（之前 56.3 / 56.8 / 52.9 / 50.9 / 47.6 / 38.5）。

## 2b. 解码器上限（示例 04 §4b；`frontend/grid.py::decoder_cap`）

§2 的“MCS 上限”是**发射机合规口径**（底板比规范的 TX EVM 要求低 3 dB）。接收机实际能带的是另一回事：EVM 底板就是一层噪声，
MCS 的 ideal 门限 T（`data/spec/per_thresholds.yaml`，本库接收机在理想链上实测的 PER 1e-2 点，79 条曲线）加上底板后需要
SNR_req = −10·log10(10^(−T/10) − 10^(floor/10))；判可达的口径是 −floor ≥ T + 3 dB（`assumed.decoder_cap_margin_db`，此时底板最多吃 3.0 dB 灵敏度）。
底板取**解析底板与该格时域 EVM 中较差的一个**（`decoder_floor_db`；C1–C3 起）：解析的功率相加在 IQ 镜像不再是小扰动时偏乐观（80 MHz 基准：1.28 GHz 差 0.4 dB、2.56 GHz 差 0.9 dB；示例 02 全部 2.56 GHz 格差 0.3–1.3 dB，2026-11-13 之前 0.3–1.2）。

### 回退的规则（2026-11-13，ROADMAP C10）

回退问题由工作点规则定下了（`assumed.pa60_operating_rule`）：取 PA 单独在类 OFDM 包络上读到 −21 dB EVM 的回退。
−21 dB 是 802.11ad 16-QAM 的 TX EVM 限，也是 60 GHz 发射机 `pa60.wu_isscc2015` 标称输出功率用的口径（限值读自那篇报告幻灯片图上标的规范线，802.11ad 条文没读，ROADMAP C10）。
预设的形状上这一点是 7.457 dB，取 `derived.pa60_obo_at_evm_limit_db` = 7.5 dB（高斯包络种子 1–5 给 7.46–7.59 dB）。示例 09 §2：

| 形状 | 从 Psat 算 dB | 从 P1dB 算 dB |
|---|---|---|
| 11ad EM（p 0.81） | 9.97 | 0.47 |
| 预设（p 1.286） | 7.46 | 2.86 |
| 汇编中位间隙（p 1.57；中位含 [1] 与 [11]，见下） | 6.74 | 3.44 |
| 预设去掉 AM/PM | 7.06 | 2.46 |

- **同一条规则放在 11ad EM 的形状上要 10.0 dB**：Liu 的 8 dB 在那颗 PA 上已越过 −21 dB 的线（PA 单独 −18.1 dB）。
- 预设从 8 dB 改到 7.5 dB：Pout 6.6 → 7.1 dBm，PA 隔离 EVM −22.1 → −21.1 dB，工作点在 P1dB 之下 2.9 dB（原来 3.4）。
- `config.tgad_em_pa(cfg)`（11ad 形状那一行灵敏度）带 Liu 的 8 dB。Liu 自己的预设（示例 00 / 01）与数值指纹不变。
- 规则读自的那颗发射机标称 9.3 dBm 对应 −21 dB（单载波 16-QAM），比它 PA 的 P1dB（7 dBm，读图）高 2.3 dB。单载波的 PAPR 比 OFDM 低，所以这只核对口径，不核对数。
- “汇编中位间隙”一行的中位（3.3 dB）取的是 Table I 全部 14 行，其中 [1]（9.0 dB，原作者自述偏置不当）与 [11]（48 / 52 GHz）本不该算进 60 GHz、偏置正常的分布（spec_sources 0.4.0 读原文得出）。这一行只用来看分布，按“偏置正常、60 GHz”重算中位不做（2026-11-14 用户定，ROADMAP E）。

ROADMAP C8 / A1 说的“预设回退上 DPD 几乎没有收益，同台表却计了 DPD 的功耗”，当时说的是 11ad EM 那颗，原因在形状：它在 8 dB 处已过 P1dB，wifitrx 的 DPD 步只能拿回 0.8 dB。测量形状在 8 dB 上能拿回 2.0 dB（−22.2 → −24.2）。回退 6 dB 两颗都拿不回来。

所以那句话对现在的预设又成立了：同台表照样计着 DPD 的功耗（§5），而这个工作点上 DPD 不买东西。规则要不要把 DPD 算进去，记在 ROADMAP C8 / C10。

### 功耗列的效率规律

功耗列按 B 类规律从峰值 PAE 往下折：PAE(Pout) = PAE_max · sqrt(Pout / Psat)。两篇给了 P1dB 处的 PAE：Asada 测 7.9 %，B 类折出 9.6 %、A 类 5.7 %；Li 测 12.0 %，B 类 11.0 %、A 类 8.4 %。一颗在两者之间，一颗比 B 类还好。规律没换。11ad EM 那颗假设的峰值 PAE 20 % 比测量的 14.3–16.3 % 高；现在的预设用 Asada 的 16.3 %。
